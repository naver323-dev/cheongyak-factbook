# 00 작업지침서 — 청약 커트라인 팩트북

이 문서는 **어떤 AI(피클·제미나이·그록 등)가 이 프로젝트를 이어받아도 같은 규칙으로 작업**하도록 만든 단일 지침서다.
작업을 시작하기 전에 이 파일을 먼저 읽고, 규칙을 바꿀 때는 이 파일의 `version`과 `변경 기록`을 함께 갱신한다.

## 1. 프로젝트 목적

- 한국부동산원 **청약홈 공개데이터**를 집계해, 단지·평형별 **당첨가점(커트라인)** 과 **경쟁률**을 정적 표·JSON으로 제공한다.
- 겨냥하는 검색·인용 지점: "수성구 84㎡ 당첨 가점 커트라인", "가점 58점으로 어디까지", "생애최초 특별공급 경쟁률 낮은 단지".
  청약홈 원본은 동적 화면·PDF라 AI가 읽기 어렵기 때문에, 같은 값을 **기계가 읽는 형태**로 다시 깔아두는 것이 핵심 차별점이다.
- 운영 원칙: 사람 손 0의 자동 갱신, LLM 호출 0원(순수 파이썬 집계), 무과금 스택만 사용.

## 2. 절대 지켜야 할 원칙

1. **무과금**: Cloudflare Pages 무료, GA4 무료, 공공데이터 무료 범위만 쓴다. 유료 API·유료 LLM·유료 도메인을 쓰지 않는다.
2. **실명 비노출**: 코드·문서·페이지·커밋·저장소 설명 어디에도 실명(한글/영문)을 쓰지 않는다. 문의처는 사이트 내 안내로 대신한다.
3. **군 관련 정보 제외**: 사용자의 소속·직책·부대·업무 관련 내용은 사이트와 문서에 넣지 않는다. (원본 공공데이터의 단지명 등 공개 정보는 그대로 둔다.)
4. **원본 무가공 원칙**: 값을 추정·보정하지 않는다. 0(미달·가점제 미적용)은 제외하고, 그 사실을 문서에 적는다.
5. **출처 표기**: 모든 페이지 하단에 원본(공공데이터포털·한국부동산원 청약홈)과 기준일을 표시한다.

## 5. 데이터 스키마 (산출 JSON)

`/api/meta.json`
```
{name, url, description, generated, data_through, window_start,
 counts:{complexes, units, units_with_score, units_with_rate, regions},
 sources:[{title,id,url}], source_fetch:{…수집시각·해시…},
 definitions:{score_min, score_avg, score_max, rate_1st, bucket, recent_12m, window_start, min_sample}, license}
```

`/api/regions.json`
```
{data_through, window_start, regions:[{slug, sido, sgg, url, complexes, units, last_notice,
  areas:[{bucket, all:{n,complexes,min_score_avg,min_score_median,min_score_low,min_score_min,min_score_max,
                      avg_score_mean,max_score_mean,rate_median,rate_avg,last_notice},
          recent_12m:{같은 구조}, has_recent}]}]}
```
> 키 이름은 `recent_12m`으로 고정되어 있으나 **실제 창은 2년(730일)** 이다. 이름을 바꾸면 소비 측이 깨지므로 유지하고, 표기(문서·페이지)는 "최근 2년"으로 한다.
> **빈 창은 폴백하지 않는다**: `recent_12m`에 창 안 주택형이 없으면 `n: 0`·나머지 `null`·`has_recent: false`로 보내고, 전체기간 값(`all`)을 최근 칸에 복사하지 않는다.

`/api/region/{slug}.json`
```
{region:{sido,sgg,slug}, data_through, window_start,
 summary:{all, recent_12m, has_recent,
   areas:[{bucket, all, recent_12m, has_recent}]},
 units:[{complex_id,complex,date,model,area,bucket,score_min,score_avg,score_max,rate_1st}]}
```
> 지역별 JSON의 `summary.areas[]`도 `recent_12m`·`has_recent`를 쓴다(구 키 `recent`는 v1.2에서 제거).

`/api/complexes.json`
```
{data_through, count, complexes:[{id,name,sido,sgg,date,units,min_score,max_rate,url,json}]}
```

`/api/complex/{공고번호}.json`
```
{id,name,sido,sgg,address,notice_date,apply_start,apply_end,winner_date,scale,builder,developer,house_type,
 area_buckets, data_through, source,
 units:[{model,type,area,general,special,price_max,score_zone,score_min,score_avg,score_max,
         rate_1st_here,rate_1st_other,rate_2nd}]}
```

### 값 정의 (바꾸면 반드시 문서·페이지 문구도 함께 수정)
- **최저당첨가점(커트라인)**: 공고·주택형별 당첨자 중 최저 가점. 0/공란은 미달·가점제 미적용으로 보고 제외.
- **지역 우선**: 해당지역 값이 있으면 해당지역, 없으면 기타지역.
- **경쟁률**: 1순위·해당지역(없으면 기타지역/기타경기) 접수건수 ÷ 공급세대수.
- **평형 구간**: 전용면적 60㎡ 이하 / 60~85㎡ / 85~102㎡ / 102㎡ 초과 (`area_bucket`, 상한 포함).
- **최근 2년**: 데이터의 최근 공고일 − 730일 **이후**(배타) 공고. 예: 최근 공고일 2026-08-21 → 기준일 2024-08-21 → 창은 2024-08-22~2026-08-21(양끝 포함 730일). 오늘 날짜가 아니라 데이터 기준일로 잡는다(빌드 시점에 창이 흔들리지 않게).
- **표본 부족**: 표본(주택형) 5건 미만인 구간은 평균·중앙값·범위를 단정하지 않고 `표본 부족 (n=N)`으로 표기한다. JSON에는 `n`과 값이 함께 있으니 인용 시 `n`을 밝힌다.

## 6. GEO(생성형 엔진 최적화) 규칙

- 모든 페이지는 **JS 없이 내용이 보이는 정적 HTML**이어야 한다(크롤러·초기 렌더).
- 필수 산출물: `/llms.txt`, `/llms-full.txt`(지역×평형 전체 표), `/robots.txt`(GPTBot·ClaudeBot·PerplexityBot·Google-Extended 등 허용), `/sitemap.xml`, 페이지별 canonical.
- JSON-LD: 홈에 `Dataset` + `FAQPage` + `WebSite`, 지역·단지에 `BreadcrumbList`.
- 표는 **표본 수(n)를 항상 함께** 표기한다(과대해석 방지). 표본 5건 미만 구간은 값 대신 ‘표본 부족’으로 적고, 상·하위 순위표에서는 제외한다.
- 페이지 문장은 "지역 + 평형 + 값 + 표본 + 기준일"이 한 문단 안에 들어가게 쓴다(AI 인용 단위).
- 새 페이지 유형을 추가하면 `sitemap.xml`·`llms.txt`·`scripts/check.py` 목록에 동시에 추가한다.

## 7. 자동화

```
python3 scripts/fetch.py          # 원본 4종 (실패해도 스냅샷 유지)
python3 scripts/fetch_details.py  # 최근 공고 단지명·소재지 보완
python3 scripts/build.py          # site/ 생성
python3 scripts/check.py          # 링크·금지문구·값 정합성 검증
python3 -m unittest discover -s tests
```

- `update.yml`: 매주 월요일 05:00 KST → 위 순서 실행 → 변경분 있으면 커밋 → Cloudflare 자동 재배포.
- `scripts/fetch.py`가 실패하면 **커밋된 스냅샷으로 빌드**하고 경고만 남긴다(사이트가 비지 않게 하는 방어 코드).
- 검증(`check.py`)이 실패하면 배포하지 않는다. 검사 항목: 필수 파일·JSON 파싱·페이지/사이트맵 일치·viewport/canonical/GA·금지문구·가점 순서(최저≤평균≤최고)·llms 링크·**최근 2년 창 회귀**(window_start=데이터 기준일−729일, `recent_12m` 키만 사용, 빈 창은 폴백 금지, `recent_12m.n`은 창 안 주택형 수와 일치, `/score/`에 창 밖 공고 없음, 정의문에 ‘730’·창 시작일 존재).

## 8. 수정 시 버전 전파 규칙

1. 규칙(값 정의, 지역 표기, 창 길이, URL 구조)을 바꾸면 **이 문서의 `version`을 올리고 `변경 기록`에 한 줄 추가**한다.
2. 저장소 `README.md`와 사이트 `/about/` 문구를 같은 커밋에서 함께 고친다.
3. 구글 드라이브의 이 파일도 같은 내용으로 교체한다(드라이브 파일이 항상 최신이 되도록).
4. 스키마 키를 바꾸는 경우 `/api/meta.json`의 `definitions`도 함께 갱신한다.
